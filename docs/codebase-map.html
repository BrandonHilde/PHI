Switches that split a problem

SettingWhat it does
PHI_IR=0Every method goes to the generator. If a problem goes away, the new path caused it. (x86 only: a macOS program has no generator behind it.)
PHI_IR32=0The same, for 32-bit programs only.
PHI_IR_SKIP=Class.MethodOne method goes to the generator. Use it to find which method is wrong.
PHI_IR_TRACE=1Says which methods went through the new path, and why the others didn't. 2 also prints each method's intermediate form.
PHI_IR_REGS=1Prints each value's live range and whether it got a register or a frame slot.
PHI_IR_VERIFY=1Says where a value is made in a register another live value has: the allocator's own mistakes.
PHI_INLINE_TRACE=1macOS programs: lists each method put in where it's called, with its form.
--target linux64 beside --target macosThe same program on the other CPU. Right on one and wrong on the other points at that back end, not at the form.
PHI_NASM, PHI_QEMU, PHI_CLANGPaths to the assemblers and the emulator, when they aren't on the PATH.
PHI_LINUX_RUNOn a Mac: the command that runs a Linux program in a Linux machine (lima, say), so phi test and phi fuzz run the x86 Linux builds too.
PHI_WINDOWS_RUNOff Windows: the command that runs a Windows program in a Windows machine (given the program's path and its arguments), so phi test --target windows64 runs there.

The phi command

CommandRuns
phi build, runThe whole pipeline, then the program (Builder.cs, HostRunner.cs, Qemu.cs)
phi test [-f NAME]tests/: build, run, compare with NAME.expected (TestRunner.cs)
phi check, fmt, lspChecks or formats without building; the editor's server (SourceCheck.cs, Formatter.cs, LanguageServer.cs)
phi fuzz code|numbers|objectsRandom programs with known output (the three *Fuzzer.cs files)
phi comparebench/ against C (gcc, or clang on a Mac) and C# (Compare.cs)
phi profile, load, serveWhere time goes; many networked machines; a test web server
dotnet testThe compiler's 659 unit tests, about 30 seconds
