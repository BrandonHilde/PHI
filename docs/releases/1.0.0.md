# PHI 1.0

The first release. The language is what this page and the [reference](../language.md)
describe; where a later version changes something a program relies on, its release notes
will say so. The format of compiled libraries (`.philib`) is the one part not promised to
stay. `phi --version` says which PHI a build is.

## What PHI is

A systems language whose compiler writes machine code itself: boot sectors, 32-bit
kernels and the programs they run, and ordinary programs for Linux and Windows in 32 or 64
bits, each one file written whole with no linker, which needs no C library and can call
any; and native programs and apps for macOS on Apple Silicon, which Apple's own tools
assemble, link and sign. Its standard library (135 modules,
about 32,000 lines of PHI) holds an operating system's parts: memory, a file system,
processes, drivers, a network stack up to TLS 1.3, graphics, windows and sound.

## The language in this version

- **Numbers and text:** whole numbers of 8 to 64 bits, `f16`, `f32` and `f64`, `bln`, `chr`,
  enums, and `str`: UTF-8 text that grows, compared and put in order (`<`, `>`), gone
  through a character at a time (`while each c in text`, with `as int`, `as u8` or `as chr`
  for another way).
- **Arrays:** of a size, up to a size (`[atmost n]`), growing (`[]`), and of more than one
  size (`int table[3][4];`, `table:r:c`), each index checked.
- **Vectors:** `vec<T>`, as many numbers as a vector register holds, worked on by one
  instruction each (`a + b`, `(a.Min: b)`, `(pixels.AddSat: tint)`, masks and `Pick`),
  read like a short array (`v:i`, `v.len`), so the same code runs on wider vectors later.
  In 64-bit programs, as SSE2, which every x86-64 CPU has, or with `--x86-64-v2` for newer
  ones; in a macOS program as NEON, with the same answers. The optimiser also makes simple loops over arrays vector code by itself (up to about
  seven times as fast for bytes), with the same answers.
- **Structs and objects:** structs with methods, interfaces called through whichever
  struct a value holds, and objects PHI allocates and frees itself (`new`, `takes`,
  `empty`), with no `delete` and no garbage collector. Every struct is laid out by one
  rule, C's (each field on a multiple of its size), so its shape is known from its
  declaration and every field `atomic` can use is aligned.
- **Types as parameters:** structs that take types (`Map<Key Value>`), methods that take
  types in a class or a struct (`Lists.Largest<int>`, `stack.Sum<i64>`), and types that
  must have an interface (`<Item has Ranked>`).
- **Errors:** `throw` and `if call ... throws err`, which also catches division by zero,
  an index out of range, a bad address and a stack that's run out, each with its line. A
  method that fails by what it answers says which answers those are
  (`[end: count throws below 0]`), and the same guard catches them, so it's one way to
  handle a failure however a method reports it; the file calls, the network's, sound's
  and the ones that start a thread or a program say theirs.
- **Control:** `if`, `when` (on numbers, enums and text), `while`, `while each`,
  `if list has x when ...`, and `exists`.
- **Close to the machine:** pointers, ports, `volatile`, interrupt handlers, `unsafe`,
  assembly blocks, threads (each with the stack it's given: `StackSize.LARGE`, or a size
  of its own), `atomic` and `locked`.
- **Libraries:** `phi build --library` makes a `.philib` another program includes with
  one `use`, with none of its source.
- **C libraries:** a Windows, macOS or 64-bit Linux program calls any C library: floats,
  64-bit numbers, structs by value, functions that take any number of values, and PHI methods
  C calls back, on any thread. `lng`, `ulng`, `isz` and `usz` are C's `long` and `size_t` as
  each system has them. Nine libraries come with PHI, whole, in the
  [vendor folder](../../vendor/README.md): raylib 6.2, SDL3 3.4.20, Vulkan 1.4, SQLite 3.54.1,
  Lua 5.5.1, zlib 1.4, stb, miniaudio 0.11.26 and C's own library. `use vendor.raylib;` is all a
  program writes, and the build puts the library beside it.

The [language reference](../language.md) has all of it.

## What it runs on

| Target | State |
|---|---|
| 16-bit boot sectors and real-mode programs | works; no heap, so no text or arrays that grow |
| 32-bit kernels, and programs on PHI OS | works; the main target |
| Linux programs, 32 and 64 bits | works |
| Windows programs, 32 and 64 bits | works; tested on a Windows 11 PC |
| macOS programs and apps (`--target macos`, `--app`), on Apple Silicon | works: built and run on a Mac with Xcode's Command Line Tools. Windows, sound, threads, the network, files, compiled libraries and calls into the system's libraries are there; what a macOS program can't do yet is an error when it's built, naming it |

The kernels and PHI OS run in QEMU. Nothing has been run on real PC hardware; macOS
programs run on the Mac itself.

## How it was checked

On three computers, each running everything it can:

- **A Mac with Apple Silicon:** 1074 runs of the 454 programs in `tests/` (as 16-bit
  programs, 32-bit kernels and PHI OS programs in QEMU, as Linux programs in 32 and 64 bits
  in a Linux machine, and as native macOS programs: 226 of the tests run as those), 660
  tests of the compiler itself, and thousands of random programs from `phi fuzz` (numbers,
  code and objects) with nothing wrong. The x86 code of every test and sample, on every
  system, is compared by its hash from one change to the next, so what changed in it, and
  why, is known.
- **A Windows 11 PC (x86-64):** 1304 of 1305 runs of the same tests, as Windows programs in
  32 and 64 bits, in QEMU and as Linux programs; the one that failed (`stopwatch`, with the
  PC busy) passes on its own. The window samples opened and drawn at both widths, a debug
  build stepped through in a debugger by PHI's lines, and a game of about a thousand lines
  moved to the vendor folder's raylib.
- **A Linux PC (Fedora 42, x86-64):** 852 of 852 runs, in QEMU and as Linux programs, with
  the optimiser and again without it; the tutorial's 9 examples; a game written against six
  of the vendor libraries at once, with its windows seen on Wayland and X11.

The vendor folder's 17 tests (each library called from its `use` line alone, and every
struct's size beside C's) pass on all four systems a program is built for, and the tests of
calling C (`tests/clib`) on each.

## What it doesn't do

- **C libraries:** not from a 32-bit Linux program or a PHI OS one. A function that takes
  any number of values is declared with the ones a call gives it (`C.printf_int`), a
  `#define` past 32 bits isn't a constant, and a struct that differs between systems
  (miniaudio's `ma_sound`) is held by its address. On Linux, SDL3 is the system's, and
  raylib's own build needs glibc 2.38.

- **Speed on macOS:** over the same benchmarks a macOS program takes 1.13 times the time of
  C built with Apple's clang 21 at `-O2`, and 0.77 times C#'s (an M1; from 0.65, `matrix`,
  to 2.1, `maps`, where the C keeps each key and value side by side and PHI's `Map` is three
  arrays). gcc and clang don't optimise these alike, so this isn't comparable with x86's
  figures below.
- **Speed:** programs are built through PHI's own optimiser, 64-bit and 32-bit (kernels,
  16-bit code and debug builds are built as before). Over the twelve benchmarks in `bench/`,
  on x86 Linux, a 64-bit program takes 1.14 times `gcc -O2`'s time and 0.74 times C#'s (.NET
  10, a release build), three runs agreeing to within 0.01
  ([bench/RESULTS.md](../../bench/RESULTS.md)). One of the twelve is `pixels`, bytes worked
  on 16 at a time with `vec<u8>`, where PHI takes 0.38 times `gcc -O2`'s time and 0.08 times
  C#'s; without it, over the eleven ordinary ones, it's 1.27 times `gcc -O2`'s and 0.90 times
  C#'s, from 0.51 (`matrix`, whose loops the optimiser makes vector code) to 1.59 (`lists`,
  whose times vary by about 7% from run to run). `fib` is the furthest from gcc, at 3.1
  times: gcc turns its recursion into a loop. Beside Microsoft's compiler on Windows (MSVC
  19.42, `/O2`), over the same twelve, PHI takes about 0.82 times its time. 32-bit programs, which
  have fewer registers, take 1.25 times as long as 64-bit ones together, and less time than
  C built without optimisation on most of the benchmarks. `PHI_IR=0` leaves every program
  to the code generator, `PHI_IR32=0` 32-bit ones (not a method that uses a `vec`, which
  only the optimiser builds), and `PHI_OPT_OFF` each step of the optimiser.
- **Other machines:** x86, and ARM for macOS programs only. No 64-bit kernels, no PHI OS on
  ARM, no Linux or Windows on ARM. A macOS program is built on a Mac (it needs Apple's
  linker), and on Intel Macs not at all.
- **macOS, what's missing:** a debugger sees lines and the methods called, not variables by
  name; `--app` signs for the Mac it's built on, and giving an app to someone else needs a
  Developer ID and Apple's notarising, done by hand; a test that hangs doesn't say where.
- **No power operator:** `^` is bitwise exclusive or, as in C. `x^^ 3;` is the statement.
- **Text past ASCII** is kept and passed on whole, but `Text.Upper`, `Text.Lower` and
  comparing without case change ASCII letters only, and text is put in order by its bytes.
- **Tools:** no packages, no debugger information on Linux, and the language server has
  no hover or renaming of its own yet. x86 code is assembled by NASM and macOS code by
  Apple's clang: PHI has no assembler of its own.
- **Compiled libraries** are at version 1.2 of their format, which isn't promised to stay:
  a `.philib` is built again for a PHI that changes it, and says so when it's loaded.

## Getting it

A download for each system is with the release: `phi-1.0.0-windows-x64.zip`,
`phi-1.0.0-linux-x64.zip` and `phi-1.0.0-macos-arm64.zip`. Each is everything: `phi` as one
file that needs no .NET, the vendor folder with its libraries for every system a program can
be built for, this documentation as HTML, the standard library's source to read, and the
samples. Unzip it anywhere and run `phi` from there. What it still needs is the assembler
and emulator it drives: NASM, QEMU for kernels and PHI OS, and on a Mac Apple's Command Line
Tools ([getting started](../getting-started.md) has each system's). On a Mac, a downloaded
`phi` is one macOS hasn't seen: `xattr -d com.apple.quarantine phi` lets it run.

Or build it from the source, as getting started describes: the .NET 10 SDK, then
`dotnet build PHI.sln`, and `python3 vendor/fetch.py` once for the vendor folder's libraries.
