# PHI 0.1.0

The first version with a number. It's a preview: the language, its library and the format
of compiled libraries can each still change between versions, and a program written for
0.1.0 may need changes for the next one. `phi --version` says which PHI a build is.

## What PHI is

A systems language whose compiler writes x86 machine code itself: boot sectors, 32-bit
kernels and the programs they run, and ordinary programs for Linux and Windows in 32 or 64
bits, with no linker and no C library. Its standard library (126 modules, about 30,000
lines of PHI) holds an operating system's parts: memory, a file system, processes, drivers,
a network stack up to TLS 1.3, graphics, windows and sound.

## The language in this version

- **Numbers and text:** whole numbers of 8 to 64 bits, `f16`, `f32` and `f64`, `bln`, `chr`,
  enums, and `str`: UTF-8 text that grows, compared and put in order (`<`, `>`), gone
  through a character at a time (`while each c in text`, with `as int`, `as u8` or `as chr`
  for another way).
- **Arrays:** of a size, up to a size (`[atmost n]`), growing (`[]`), and of more than one
  size (`int table[3][4];`, `table:r:c`), each index checked.
- **Vectors:** `vec<T>`, as many numbers as a vector register holds, worked on by one
  instruction each (`a + b`, `(a.Min: b)`, `(pixels.AddSat: tint)`, masks and `Pick`),
  read like a short array (`v:i`, `v.len`), so the same code runs on wider vectors later.
  In 64-bit programs, as SSE2, which every x86-64 CPU has, or with `--x86-64-v2` for newer
  ones. The optimiser also makes simple loops over arrays vector code by itself (up to about
  seven times as fast for bytes), with the same answers.
- **Structs and objects:** structs with methods, interfaces called through whichever
  struct a value holds, and objects PHI allocates and frees itself (`new`, `takes`,
  `empty`), with no `delete` and no garbage collector. Every struct is laid out by one
  rule, C's (each field on a multiple of its size), so its shape is known from its
  declaration and every field `atomic` can use is aligned.
- **Types as parameters:** structs that take types (`Map<Key Value>`), methods that take
  types in a class or a struct (`Lists.Largest<int>`, `stack.Sum<i64>`), and types that
  must have an interface (`<Item has Ranked>`).
- **Errors:** `throw` and `if call ... throws err`, which also catches division by zero,
  an index out of range, a bad address and a stack that's run out, each with its line.
- **Control:** `if`, `when` (on numbers, enums and text), `while`, `while each`,
  `if list has x when ...`, and `exists`.
- **Close to the machine:** pointers, ports, `volatile`, interrupt handlers, `unsafe`,
  assembly blocks, threads (each with the stack it's given: `StackSize.LARGE`, or a size
  of its own), `atomic` and `locked`.
- **Libraries:** `phi build --library` makes a `.philib` another program includes with
  one `use`, with none of its source.

The [language reference](../language.md) has all of it.

## What it runs on

| Target | State |
|---|---|
| 16-bit boot sectors and real-mode programs | works; no heap, so no text or arrays that grow |
| 32-bit kernels, and programs on PHI OS | works; the main target |
| Linux programs, 32 and 64 bits | works |
| Windows programs, 32 and 64 bits | builds; tested on Windows by hand, not by this release's automated run (through the optimiser, new in this version) |

The kernels and PHI OS run in QEMU. Nothing has been run on real hardware.

## How it was checked

On Linux, for this version: 820 programs in `tests/` built and run (as 16-bit programs,
32-bit kernels, PHI OS programs and Linux programs in 32 and 64 bits; the programs through
the optimiser, and again without it), 657 tests of the compiler itself, the tutorial's 9
examples, the code libraries' tests (a web engine with HTML, CSS and JavaScript, fonts,
images, compression) and PHI-OS's, and thousands of random programs from `phi fuzz`
(numbers, code and objects, with the optimiser and without) with nothing wrong. In one earlier run a network test (`net_dns` on a virtio card) passed only on its second try.

## What it doesn't do

- **Speed:** 32-bit code is about as fast as C built without optimisation. 64-bit
  programs are built through PHI's own optimiser and are about as fast as C# (.NET 10, a
  release build) on the eleven ordinary benchmarks in `bench/`: 0.90 times its time
  together, from 0.53 (`matrix`, whose loops the optimiser makes vector code) to 1.29 each,
  and 1.29 times `gcc -O2`'s. On `pixels`, bytes worked on 16 at a time with `vec<u8>`, it
  takes 0.39 times `gcc -O2`'s time and 0.09 times C#'s ([bench/RESULTS.md](../../bench/RESULTS.md)).
  The optimiser doesn't take every method yet (text, objects copied or handed over, and
  system calls are built as before), and `PHI_IR=0` turns it off (not for a method that uses a `vec`,
  which only the optimiser builds).
- **Other machines:** x86 only. No ARM, no macOS, no 64-bit kernels.
- **Calling C:** a program can call a Windows library's functions with whole numbers and
  pointers; floats, and anything on Linux or PHI OS, aren't there.
- **No power operator:** `^` is bitwise exclusive or, as in C. `x^^ 3;` is the statement.
- **Text past ASCII** is kept and passed on whole, but `Text.Upper`, `Text.Lower` and
  comparing without case change ASCII letters only, and text is put in order by its bytes.
- **Tools:** no packages, no debugger information on Linux, and the language server has
  no hover or renaming of its own yet.
- **Compiled libraries** are at version 1.2 of their format, which isn't promised to stay:
  a `.philib` is built again for a PHI that changes it, and says so when it's loaded.

## Getting it

There are no built downloads for 0.1.0. Build it from the source, as
[getting started](../getting-started.md) describes: the .NET 10 SDK, NASM and QEMU, then
`dotnet build PHI.sln`.
